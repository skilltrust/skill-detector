# SP-1.1 — Tighten Scanner Scope to AI-Agent Files

**Date:** 2026-05-19
**Author:** Glib
**Status:** Draft for review
**Parent PRD:** `_bmad-output/planning-artifacts/prd.md` (SkillTrust MVP)
**Predecessor:** SP-1 (`docs/superpowers/specs/2026-05-18-sp1-multi-axis-engine-design.md`)
**Folds into release:** v0.2.0 (this hotfix lands on the `sp1-multi-axis-engine` branch before tagging)

## Purpose

Real-world dogfooding of the SP-1 release candidate revealed that `skill-detector` walks every scannable file in the tree and fires every rule by extension — producing 74,132 findings on a typical Next.js/Prisma repo (≈99% noise from `node_modules/` and `.claude/settings.local.json` permission strings being misread). The PRD scopes the product to AI-agent files only (`SKILL.md`, `CLAUDE.md`, `.claude/settings.json`, hooks, MCP configs). This hotfix realigns scanner behavior with that positioning.

## Scope

**In scope:**
- New `pkg/scanner/gitignore.go` wrapper around `github.com/sabhiram/go-gitignore`.
- `pkg/scanner/discover.go` honors `.gitignore` (root only) + hardcoded skip-dirs.
- New `IsSkillManifest` and `IsAgentFile` predicates in `pkg/rules/fileclass.go`.
- New `isInClaudeOrCodexDir` helper for rules whose scope includes arbitrary files in agent-config dirs.
- Path gates added to all 14 existing rules (SD-001..SD-014). New SP-1 rules unchanged.
- CLI flag `--scan-all` to bypass the scope tightening (escape hatch for migration or whole-repo audits).
- Existing `testdata/malicious/<rule>/*.<ext>` fixtures renamed to agent-file shape (e.g., `SKILL.md`, `CLAUDE.md`).
- New end-to-end repo scoping test + real-world regression test.
- CHANGELOG entry amended for v0.2.0 to document the scope behavior.

**Out of scope (named, explicit):**
- Context-aware rule firing (e.g., recognizing that a URL inside `permissions.allow` is a declaration, not a network call) → SP-2.
- Nested `.gitignore` files (only root-level loaded) → SP-2 if real-world need shows up.
- Confidence-score adjustments → SP-2.
- Adding new rules.
- Reporter/JSON schema changes (none).
- CLI surface beyond `--scan-all` (no other flags added or changed).

## Design Decisions (locked)

| Decision | Choice | Why |
|---|---|---|
| Default scope behavior | **Tighten default + `--scan-all` escape hatch** | Product must match positioning out of the box. Legacy users have a path forward. |
| Rule scoping mechanism | **Add path gates to existing 14 rules** | Mirrors the SP-1 rule design pattern. Defensive — rules fail safe even if the walker emits an unexpected file. |
| Walker filtering | **Honor `.gitignore` (root only) + hardcoded skip-dirs** | Matches developer expectations. The hardcoded list catches dirs that aren't always gitignored. |
| Testdata fixture handling | **Rename to agent-file shape (Option A)** | Removes synthetic test-vs-production ambiguity; existing fixtures are pretending to be agent files anyway. |
| Versioning | **Fold into v0.2.0 — don't tag yet** | Avoid ever shipping a known-broken default. v0.2.0 = "multi-axis engine + proper scoping." |

### Walker changes (`pkg/scanner/discover.go`)

**Hardcoded skip-dirs** (always, regardless of `.gitignore`):
```go
var alwaysSkipDirs = map[string]bool{
    "node_modules": true,
    "vendor":       true,
    "dist":         true,
    "build":        true,
    "target":       true,
    ".next":        true,
    ".git":         true,
}
```

**`.gitignore` loading** (best-effort, root only):
```go
// In Discover(root) before the walk:
ignoreMatcher, _ := loadGitignore(root)  // nil if missing
```

**Walker loop additions** (in order, before existing extension check):
1. If entry is a dir AND `alwaysSkipDirs[name]` → `return filepath.SkipDir`.
2. If `ignoreMatcher != nil` AND `ignoreMatcher.MatchesPath(relPath)`:
   - If dir → `return filepath.SkipDir`
   - If file → `return nil` (skip silently)
3. Existing hidden-dir allowlist logic (`.claude`, `.codex`, `.opencode` walked; others skipped) — unchanged.
4. Existing extension filter — unchanged.

**`--scan-all` mode**: when set, skip steps 1 and 2 (both hardcoded and gitignore checks). Step 3 (hidden-dir allowlist) still applies — even under `--scan-all`, walking `.git/` provides no value.

### New `pkg/scanner/gitignore.go`

```go
package scanner

import (
    "os"
    "path/filepath"

    ignore "github.com/sabhiram/go-gitignore"
)

// loadGitignore reads <root>/.gitignore if present and returns a matcher.
// Returns (nil, nil) when no .gitignore exists — caller treats as no-op.
// Returns (nil, err) only on read errors that aren't "not exists".
func loadGitignore(root string) (*ignore.GitIgnore, error) {
    path := filepath.Join(root, ".gitignore")
    if _, err := os.Stat(path); os.IsNotExist(err) {
        return nil, nil
    } else if err != nil {
        return nil, err
    }
    return ignore.CompileIgnoreFile(path)
}
```

### Rule scoping (`pkg/rules/fileclass.go`)

Two new exported predicates:
```go
// IsSkillManifest returns true for SKILL.md or skill.yaml — the original
// product scope before SP-1 expanded it.
func IsSkillManifest(path string) bool {
    base := filepath.Base(filepath.ToSlash(path))
    return base == "SKILL.md" || base == "skill.yaml"
}

// IsAgentFile is the union predicate covering every file class the product
// inspects: skill manifests + CLAUDE.md + .claude/settings.json + .mcp.json.
// Use this as the default gate in rules that don't need to discriminate.
func IsAgentFile(path string) bool {
    return IsSkillManifest(path) || IsClaudeMD(path) ||
           IsClaudeSettings(path) || IsMCPConfig(path)
}
```

One new unexported helper:
```go
// isInClaudeOrCodexDir returns true for any path under .claude/, .codex/,
// or .opencode/. Used by rules that inspect arbitrary files in agent
// config dirs (e.g., hook scripts at .claude/scripts/foo.sh).
func isInClaudeOrCodexDir(path string) bool { ... }
```

## Testdata migration

The existing rule unit tests reference fixtures like `testdata/malicious/credential-theft/secret.md`. After scope gating, these tests fail because `secret.md` is not an agent file.

**Migration approach (Option A): rename fixtures to agent-file shape.**

| Before | After |
|---|---|
| `testdata/malicious/credential-theft/secret.md` | `testdata/malicious/credential-theft/SKILL.md` |
| `testdata/malicious/prompt-injection/hidden.md` | `testdata/malicious/prompt-injection/CLAUDE.md` |
| `testdata/malicious/shell-injection/inject.sh` | (untouched — script files inside `.claude/`-style dir not needed; SD-001 also has `isInClaudeOrCodexDir`; move under `testdata/malicious/shell-injection/.claude/scripts/inject.sh`) |
| `testdata/malicious/supply-chain/<file>` | Rename to `SKILL.md` or `package-lock.json`-equivalent inside agent-file scope |
| etc. |

The migration is mechanical and preserves test intent: a malicious-content fixture that previously triggered a rule continues to trigger the rule, but now lives at a path the product actually inspects.

Each test that hardcoded the fixture path is updated to point at the new location. No test logic changes.

Estimated ~30 fixture files to rename, ~15-20 test files to update.

## CLI behavior matrix (after this hotfix)

| Invocation | Walker behavior | Rule firing |
|---|---|---|
| `skill-detector scan .` | Honors `.gitignore`, skips hardcoded dirs | Only on agent files |
| `skill-detector scan --scan-all .` | Walks everything except `.git/` | Only on agent files (rules still path-gated) |
| `skill-detector scan path/to/.claude/settings.json` | Walks the single file | Settings rules fire normally |
| `skill-detector scan testdata/malicious/credential-theft/` | Walks; finds `SKILL.md` | SD-006 fires (after fixture rename) |

`--scan-all` notably does NOT undo the rule-level path gating — even when walking node_modules, the rules still skip it. This is intentional: the rules are about agent files; walking more files doesn't change what's interesting. `--scan-all` is for migration / debugging only.

## Testing strategy

Four layers:

### Layer 1: Walker unit tests (`pkg/scanner/discover_test.go`)

| Test | Verifies |
|---|---|
| `TestDiscoverSkipsHardcodedDirs` | `node_modules/`, `vendor/`, `dist/`, `build/`, `target/`, `.next/` never walked |
| `TestDiscoverRespectsGitignore` | Fixture with `.gitignore` containing `secret.md`; `secret.md` not discovered |
| `TestDiscoverGitignoreNegation` | `.gitignore` with `*.md\n!CLAUDE.md`; `CLAUDE.md` is discovered |
| `TestDiscoverMissingGitignore` | No `.gitignore`; walker behaves as today (with hardcoded-dir skip still in effect) |
| `TestScanAllOverridesGitignore` | `Discover(root, Options{ScanAll: true})` walks gitignored files |
| `TestScanAllStillSkipsGitDir` | Even under `--scan-all`, `.git/` is skipped |

### Layer 2: Per-rule path-gating tests

For each of the 14 existing rules, append a `TestSDxxx_GatesNonAgentFile` test using the pattern:
```go
content := []byte(<malicious pattern that DOES trigger this rule on agent files>)
ctx := model.FileContext{Path: "node_modules/foo/README.md", Ext: ".md", Content: content}
registry := NewRegistry()
RegisterXxxRules(registry)
findings := []model.Finding{}
for _, r := range registry.RulesFor(".md") {
    findings = append(findings, r.Match(content, ctx)...)
}
// assert no SD-xxx findings
```

14 small tests, mechanical and uniform.

### Layer 3: End-to-end repo scoping test (`cmd/skill-detector/scope_test.go`)

Synthetic temp-dir fixture:
- `node_modules/eslint/README.md` with "ignore previous instructions"
- `package-lock.json` with a post-install hook entry
- `.claude/settings.json` with `Bash(curl *)`
- top-level `README.md` with various patterns

Two test runs:
- Default (`--scan-all=false`): only the `.claude/settings.json` finding appears (SD-017 Bash wildcard).
- `--scan-all=true`: more findings appear (the previously-skipped sources can now produce findings — though only on agent files due to rule gating; pattern: SD-017 still the main hit since other files are not agent files).

### Layer 4: Real-world regression test (`cmd/skill-detector/scope_real_repo_test.go`)

Build a larger fixture mimicking a real Node.js project layout: `node_modules/`, `.claude/`, `src/`, `prisma/`, `package-lock.json`. Run scan. Assert total finding count under a sanity threshold (initial budget: `< 100`; calibrate after first run). Assert at least the expected SD-017 finding from `.claude/settings.json` fires.

This test catches future regressions where someone removes a path gate or breaks the gitignore handling.

### What still passes (regression evidence)

- All SP-1 layer tests continue to pass (rule unit tests, grade aggregator tests, CVE reproducers, binary E2E).
- `go vet ./...`, `go build ./...`, `go test ./...` all clean.

## Migration & compatibility

### Behavior changes for v0.1.x users upgrading to v0.2.0

| Before | After |
|---|---|
| `skill-detector scan .` walked every `.md`/`.json`/etc. | Walks only agent files. Use `--scan-all` to opt back into walking everything (rules still gate). |
| `node_modules/` scanned | Skipped (always, even with `--scan-all`). |
| `.gitignore` ignored | Honored by default. |
| Existing 14 rules fired on any matching extension | Fire only on agent files. |

### Documented in CHANGELOG

The CHANGELOG entry for v0.2.0 (already drafted in SP-1) gets a new "### Scope" subsection:

```
### Scope
- Scanner default behavior: walks only AI-agent configuration files
  (SKILL.md, CLAUDE.md, .claude/settings*.json, .mcp.json) plus
  arbitrary files inside .claude/, .codex/, .opencode/ dirs.
- Honors .gitignore at the scan root (best-effort; missing or
  malformed .gitignore is a no-op).
- Hardcoded skip-list: node_modules, vendor, dist, build, target,
  .next, .git — always skipped, regardless of .gitignore.
- New --scan-all flag bypasses scope tightening and .gitignore
  filtering. For migration or whole-repo audits.
- All 14 pre-SP-1 rules now gate by path; they previously fired on
  any file with a matching extension. This is a breaking change
  vs. v0.1.x default behavior; --scan-all + the rules' built-in
  path gating means walking more files won't reproduce v0.1.x
  output exactly.
```

### `registry.Checksum()` consequence

The 14 rule files change (Match() bodies gain the gate). The Checksum value changes from `7f422bc43d109e2b` to a new value. This is documented in CHANGELOG; release artifacts ship with the new ldflag value.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| `sabhiram/go-gitignore` dep surprises (license/supply chain) | Low | Pinned version; vendored go.sum; existing supply-chain policy. |
| Path gate accidentally blocks legitimate finding | Low | Layer 2 tests assert each rule still fires on agent-file fixtures. Testdata rename forces every test to exercise the new scope. |
| Real-world test threshold too loose/tight | Medium | Calibrate from first run, encode actual count + 20% slack. |
| `--scan-all` interacts oddly with `--fail-on-axis` | Low | One regression test covers the combination. |
| Test rename misses a hardcoded path somewhere | Medium | `go test ./...` will fail loudly; mechanical fix per failure. |
| Discover behaves differently when scanning a single file (no `.gitignore` lookup makes sense at file root) | Medium | `loadGitignore` is best-effort; single-file scans skip the lookup naturally. |
